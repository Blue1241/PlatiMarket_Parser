# Plati Radar

Нативное desktop-приложение с GUI на `egui/eframe` и CLI-парсер для анализа карточек и продавцов Plati.Market. Интерфейс desktop-приложения работает непосредственно с Rust-функциями — без WebView и локального HTTP-сервера. Дополнительно сохранен отдельный браузерный режим на `axum`; HTTP-запросы выполняются через `reqwest`, HTML разбирается `scraper`.

Основные сценарии: поиск предложений по запросу, проверка реальной стоимости выбранного тарифа в карточке, анализ продавцов и ежедневный мониторинг динамики продаж и конкуренции.

## Требования

- Rust toolchain с Cargo (edition 2021).
- Доступ к интернету для запросов к Plati.Market и API Digiseller.
- Для нативного режима порт не нужен. Для отдельного браузерного режима свободный локальный порт (по умолчанию `8080`).

## Запуск приложения

### Нативное desktop-приложение

Запуск без подкоманды открывает отдельное приложение на `egui/eframe`. Оно не запускает браузер, WebView или локальный HTTP-сервер; для запросов к Plati.Market нужен доступ в интернет.

```bash
cargo run --release
```

### Веб-приложение (дополнительный режим)

Для запуска сохранённого браузерного интерфейса:

```bash
cargo run --release -- serve --port 8080
```

Откройте <http://localhost:8080>. Нативный интерфейс и CLI доступны независимо от этого режима.

Чтобы посмотреть параметры приложения и конкретной команды:

```bash
cargo run -- --help
cargo run -- deals --help
```

Отчёты по умолчанию сохраняются в `output/`. Путь можно изменить глобальным параметром `--out-dir`:

```bash
cargo run --release -- --out-dir ./radar-data serve --port 8080
```

## Возможности приложения

### Поиск выгодных карточек

- Поиск по запросу с ограничением числа страниц и фильтрами по отзывам, негативным отзывам и минус-словам.
- Быстрые запросы для ChatGPT Plus, Claude Pro, Spotify Premium, Xbox Game Pass, YouTube Premium, Telegram Stars и пополнения Steam.
- Дополнительная проверка опций Digiseller: расчёт цены выбранного тарифа с учётом модификаторов, а не только цены на витрине.
- Просмотр вариантов и тарифов карточки, сортировка, фильтрация результатов и выгрузка CSV/JSON.

### Проверка продавца

Разбор HTML-витрины по ссылке или числовому ID. Из результатов поиска можно открыть профиль продавца и посмотреть доступную статистику: продажи, отзывы, возвраты, рейтинг и товары.

### База продавцов

Сбор продавцов по поисковым запросам, построенным из разделов `cats.xml`, с возможностью дополнить данные HTML-профилями. Результат можно выгрузить в CSV.

### Радар пустых ниш

Радар собирает данные по названиям разделов из `cats.xml`, сохраняет счётчики продаж `numsold` и сравнивает их между снимками. В таблице доступны:

- прирост продаж карточки между снимками;
- число найденных похожих карточек и разных продавцов;
- цена и её отклонение от медианы похожих предложений;
- составной балл возможности, учитывающий динамику продаж, конкуренцию и относительную наценку;
- фильтры по категории, приросту, числу продавцов, цене, наценке и тексту;
- сортировка, локально сохраняемое избранное, CSV-экспорт и график истории.

В нативном интерфейсе избранное хранится в `output/niche_favorites.json`. Флажок **«Оповещать о совпадениях»** показывает сообщение в приложении после снимка, если найдены строки, подходящие под заданные пороги. Уведомления ОС не используются. Браузерные уведомления доступны только в дополнительной веб-версии и работают, пока открыта страница.

## Радар ниш: сбор и интерпретация данных

- При запуске нативного приложения фоновая задача проверяет, нужен ли новый снимок. Первый сбор начинается автоматически; далее обновление выполняется примерно раз в сутки, пока приложение открыто. Веб-режим сохраняет прежнее поведение.
- Во время ручного и автоматического сбора интерфейс показывает число завершённых категорий, текущую активность запросов и число обработанных страниц.
- Промежуточные данные каждой завершённой категории сохраняются на диск. Если процесс завершить или он аварийно остановится, при следующем запуске сервер продолжит сбор с последней полностью сохранённой категории; незавершённая категория будет запрошена заново. Повторный запрос к радару не создаёт второй параллельный сбор.
- Завершённые снимки остаются в локальной истории и доступны после перезапуска приложения. Нативный интерфейс читает их непосредственно с диска.
- Поисковый API запрашивается страницами по 500 результатов; ошибки отдельных запросов повторяются. Продолжительность сбора зависит от количества страниц и доступности API.
- `numsold` — накопительный счётчик. Для таблицы трендов используется предыдущий снимок, снятый не менее чем за 20 часов до текущего. Поэтому для расчёта Δ в таблице нужно дождаться следующего подходящего снимка.
- График истории может показать прирост между любыми двумя соседними снимками; наведите курсор на точку, чтобы увидеть фактическую длительность интервала. Это позволяет увидеть данные уже при снимках, снятых с интервалом меньше 20 часов, не выдавая их за суточный прирост.
- Группировка похожих карточек основана на нормализации слов заголовка и удалении ряда типовых слов, а не на полноценной семантической модели. Проверьте предложения вручную перед принятием коммерческого решения.
- Балл возможности — эвристическая сортировка для удобства исследования, а не прогноз продаж или гарантия прибыльности.

Снимки хранятся в `output/niche_snapshots/`, агрегированная история — в `output/niche_history.json`. Каждый снимок — JSON с временем сбора, числом обработанных разделов и найденными карточками. Данные локальные и не отправляются в отдельное хранилище приложением.

## CLI-команды

### Поиск карточек

```bash
cargo run --release -- deals \
  --query "ChatGPT Plus" \
  --pages 2 \
  --min-reviews 100 \
  --max-neg-percent 5 \
  --option-keyword plus
```

Результат выводится в терминал и сохраняется в `deals.csv` и `deals.json`. Основные параметры: `--query`, `--pages`, `--min-reviews`, `--max-neg-percent`, `--option-keyword`, `--exclude`, `--inspect-limit`, `--sort`, `--concurrency`, `--delay-ms`. Допустимые варианты `--sort`: `real-price`, `store-price`, `reviews`, `smart`.

### Проверка одной витрины

```bash
cargo run --release -- single --url "https://plati.market/seller/siberiaplay/1257289/"
```

Вместо ссылки можно передать числовой ID продавца. Отчёт сохраняется в `plati_sellers.csv` и `plati_sellers.json`.

### Сбор продавцов

```bash
cargo run --release -- discover \
  --max-categories 20 \
  --pages-per-category 1 \
  --enrich-limit 25 \
  --concurrency 4 \
  --delay-ms 300
```

Команда сохраняет базу продавцов в CSV и JSON. Она позволяет ограничить количество категорий, глубину поиска и число профилей для HTML-обогащения.

## Файлы и данные

По умолчанию приложение использует каталог `output/`:

| Файл или каталог | Содержимое |
|---|---|
| `deals.csv`, `deals.json` | Последний результат поиска карточек |
| `plati_sellers.csv`, `plati_sellers.json` | Результат сбора или проверки продавцов |
| `niche_radar.csv` | Экспорт таблицы радара из нативного интерфейса |
| `niche_favorites.json` | Избранные карточки радара в нативном интерфейсе |
| `niche_snapshots/<timestamp>.json` | Завершённые слепки карточек и накопительных `numsold` |
| `niche_history.json` | История положительного прироста и длительности интервала между соседними снимками |
| `niche_progress.json` | Последний статус сбора для индикатора прогресса |
| `niche_checkpoint.json` и `niche_checkpoint_categories/` | Манифест и кэш категорий для возобновления прерванного сбора |

Каталог `output/` исключён из Git через `.gitignore`. При смене `--out-dir` сервер будет читать и записывать данные уже в указанный каталог. Если сервер не запущен, автоматические ежедневные снимки не выполняются.

## HTTP API

Веб-интерфейс использует API самого приложения:

| Метод и путь | Назначение |
|---|---|
| `GET /` | Веб-интерфейс |
| `GET /api/initial` | Последний сохранённый результат поиска карточек |
| `POST /api/deals` | Поиск карточек; тело — параметры поиска в JSON |
| `GET /api/item-options?id=<ID>` | Варианты и тарифы карточки |
| `GET /api/seller?url=<URL>` | Анализ витрины продавца |
| `POST /api/discover-sellers` | Сбор продавцов; JSON-параметры `max_categories`, `enrich_limit` |
| `GET /api/niche-radar` | Последние данные радара и история |
| `POST /api/niche-radar` | Запустить сбор в фоне или присоединиться к уже запущенному |
| `GET /api/niche-radar/status` | Получить прогресс, состояние checkpoint и признак выполняющегося сбора |

Эти маршруты предназначены для интерфейса и локальной интеграции; отдельная аутентификация в приложении не настроена. Не публикуйте сервер в недоверенную сеть без дополнительной защиты.

## Ограничения и замечания

- Радар строит запросы из названий разделов sitemap и анализирует выдачу поискового API. Это не подтверждённая фильтрация по внутреннему ID категории; полнота и состав результатов зависят от выдачи Plati.Market.
- Изменение ассортимента и состава результатов может влиять на агрегаты. Для интерпретации прироста важны обе даты снимков и число сопоставленных карточек.
- Доступность, формат и ограничения публичных API могут меняться. При ошибках сервиса часть данных может отсутствовать.
- Приложение предназначено для аналитики публично доступных предложений. Соблюдайте условия использования сайта и разумную частоту запросов.
